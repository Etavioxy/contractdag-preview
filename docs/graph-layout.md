# vscode-contractdag-preview — Graph Layout

- **本文档范围**：契约模型与节点高度到坐标表的换算，以及连线的端点落在哪。像素呈现归 `panel-ui.md`，面板与 VS Code 的接缝归 `vscode-integration.md`。
- **纯函数**：入参是模型与尺寸，出参是坐标表；不读时钟、不读 DOM，宿主侧可直接单测。
- **只由节点与边算出**：注释不进模型，也不参与布局。
- **坐标的期望值只有一处**：样例图上该出现哪些坐标记在 `concrete-insight.md`，本文写算法；核对时以那份的表格为准。

## 输入与输出

`layout(model, options)` 收 `ContractModel` 与可选项，回 `Map<名字, NodeBox>`；`NodeBox` 是 `{x, y, width, height}`，单位是内容坐标系的像素，与缩放无关。

| 选项 | 默认 | 作用 |
|---|---|---|
| `direction` | `TB` | 流动方向 |
| `gap` | 48 | 相邻层之间的最小空隙；缝上标签多时按跨缝标签数变高 |
| `gapCross` | 40 | 同层相邻节点之间的空隙 |
| `nodeWidth` | 160 | 框宽 |
| `nodeHeight` | 56 | 框高 |
| `marginX` / `marginY` | 80 / 24 | 画布左上留白 |

默认值集中在 `layoutDefaults`，样例坐标按它算。

## 分层

- 层归属与层内次序由 d3-dag 的 `sugiyama` 给出，坐标不取它的输出——它把层距定成 `nodeSize + 1`，样式区的 `gap` 就落不成整数格。
- 同一层的判定按层距的一半切：层内节点共用同一个流动坐标，层内次序沿用 d3-dag 的交叉最小化结果。
- 模型里有环时，按出现顺序摘掉会成环的那条边再分层；被摘的边照画，端点仍按两端的框算。

## 层距与格位

- 层距 = 流动方向上的框长 + 层间空隙；TB 下算高度，LR 下算宽度。
- 跨缝标签数：从缝上游那一层出发的边，各自产物条数之和；一条边只算它出发的那条缝。
- 层间空隙 = `gap` + `labelSpacing` × (跨缝标签数 − 1)：`gap` 是下限，缝上要放的标签越多，这一层越高。两个常量都在 `layout.ts`。
- 格位 = 交叉方向上的框长 + `gapCross`；同层节点沿该方向依次排开，整层居中于最宽的一层。

## 方向

| 写法 | 流动方向 | 层内方向 |
|---|---|---|
| `TB`（`TD` 读入时归一为它） | 自上而下 | 左右 |
| `BT` | 自下而上 | 左右 |
| `LR` | 自左而右 | 上下 |
| `RL` | 自右而左 | 上下 |

`BT` 与 `RL` 只反转层的位置，层内次序不变。

## 连线端点

- 起点在源框朝向目标那条边的中点，终点在目标框对应的中点。
- 终点沿连线方向回退一段留给箭头，回退量是 `payload.ts` 的 `arrowroom`；布局不画箭头，只保证框的位置让终点落在框边上。

端点的计算落在 `buildPreviewPayload`：它先取本文件给的框，再把两端接到框边上。
